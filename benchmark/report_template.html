Migration Performance Benchmark

Episode

Overview

The headline results for the selected episode (or the whole run). A run can contain up to three migrations: the primary one, an in-app Retry round, and a Try Again migration. Each tab after this one explains a single graph in detail.

Transfer throughput & ETA

What it tracks: how fast data is being copied from the old PC to the new PC, plus the copy engine's own estimate of time remaining.

Axes: bottom = elapsed time (minutes). Left = copy speed in MB/s. Right = ETA in minutes.

How to read: a higher blue line means faster copying. Dips show moments the transfer slowed down. The red ETA line should slope down toward zero; if it climbs, the transfer is struggling.

  • Instant speed - how fast data is moving (rclone progress line, every 5 seconds).
  • Average speed - the running average of the instant speed.
  • ETA (minutes left) - the engine's estimate; read it on the right-hand axis.

CPU usage per program

What it tracks: how much of the whole machine's processor each migration program is using, tick by tick.

Axes: bottom = elapsed time (minutes). Left = processor used, as a percentage of the whole PC (0-100%).

How to read: a line sitting near 100% means the CPU is the bottleneck. "Everything" usually spikes at the start (while it scans files) then drops off.

    Memory usage per program

    What it tracks: how much RAM (resident memory) each program is holding.

    Axes: bottom = elapsed time (minutes). Left = memory in megabytes (MB).

    How to read: stable or gently rising-and-falling lines are healthy. A line that keeps climbing and never comes back down can signal a memory leak.

      Disk I/O

      What it tracks: how much data each program reads from and writes to disk each second, plus the system-wide total.

      Axes: bottom = elapsed time (minutes). Left = disk throughput in MB/s (read + write).

      How to read: if the system line is high and flat (maxed out) while the Throughput graph is low, the disk is the bottleneck.

        Network throughput

        What it tracks: how much data is received and sent over the network (system-wide) each second.

        Axes: bottom = elapsed time (minutes). Left = network throughput in MB/s.

        How to read: compare with the Disk I/O tab. Network low while disk is maxed means the disk is the limit; network maxed while disk is not means the connection is.

          Phase durations

          What it tracks: how long each stage of the migration took, from the engine's own audit timestamps.

          Axes: bottom = duration in seconds. Each row (top to bottom) is one stage in the order it ran.

          How to read: the longest bar is where most of the time went. Time the audit trail does not cover is shown in grey as an estimate.

          • File transfer - the actual file copy; usually the dominant stage.
          • Measured stage - duration taken directly from the app's own timestamps.
          • Estimated stage - not timed by the app, so the value is approximate.

          Data per drive

          What it tracks: how much data came from each drive on the old PC, split by what happened to it.

          Axes: bottom = one bar per drive. Left = data in gigabytes (GB).

          How to read: the left segment (Copied + Failed/incomplete) is this session's own transfer attempt -- the two stack to its own total. "Already existed" is shown as a separate bar, not stacked with the others: CDM.db tracks it as a running total for this destination drive, not as part of what this specific migration selected, so it is not arithmetically part of the same whole.

          • Copied - new data transferred to the new PC this session.
          • Failed / incomplete - selected for this session's transfer but not completed.
          • Already existed - matching data already on the new PC (a separate, cumulative figure for this drive -- not part of this session's own total).

          File outcomes

          What it tracks: the number of files by what happened to each one (count, not size).

          How to read: each slice of the ring is one outcome. A large red slice means many files could not be copied; see the Skip reasons tab.

          • Copied - successfully transferred.
          • Already existed - identical file already on the new PC.
          • Skipped - could not be copied.
          • Backed up - an existing new-PC file was moved aside before copying.

          Skip reasons

          What it tracks: for skipped files, the reason, grouped into categories.

          Axes: bottom = number of files. Each row is one reason, largest at the top.

          How to read: the top bar is the biggest cause of skipped files.

          • Files skipped - count of files that could not be migrated, per reason.

          Transfer settings used

          What it shows: the settings the copy engine ran with. They control how files are copied and are the knobs to change to speed things up.

          Where they live: the engine's deployed .exe.config, read by DellDataManager.
