Transfer throughput & ETA

What it tracks: how fast data is being copied from the old PC to the new PC, over the whole migration, plus the live estimate of time remaining.

Axes: bottom = elapsed time (minutes from start). Left = copy speed in MB/s. Right = ETA in minutes.

How to read: a higher blue line means faster copying. Dips show moments the transfer slowed down. The red ETA line should slope down toward zero — if it climbs, the transfer is struggling.

  • Instant speed — how fast data is moving right now (spiky, sampled every 5 seconds).
  • Average speed — the smoothed running average, the overall pace.
  • ETA (minutes left) — estimated time remaining; read it on the right-hand axis.

CPU usage per program

What it tracks: how much of the processor each of the four migration programs is using, moment by moment.

Axes: bottom = elapsed time (minutes). Left = processor used, as a percentage (0–100%).

How to read: a line sitting near 100% means that program is processor-limited — the CPU is the bottleneck. "Everything" usually spikes at the start (while it scans your files) then drops off.

    Memory usage per program

    What it tracks: how much RAM (memory) each program is holding during the migration.

    Axes: bottom = elapsed time (minutes). Left = memory used, in megabytes (MB).

    How to read: stable or gently rising-and-falling lines are healthy. Watch for a line that keeps climbing and never comes back down — that can signal a memory leak. rclone using more memory while copying large files is normal.

      Disk I/O — new PC

      What it tracks: how much data is being read from and written to the new PC's disk each second — mostly by rclone as it saves the incoming files.

      Axes: bottom = elapsed time (minutes). Left = disk throughput in MB/s.

      How to read: if this line is high and flat (maxed out) at the same time the Throughput graph is low, the disk is the bottleneck — the PC simply cannot write files any faster. (That is the story in this sample run.)

        Network throughput

        What it tracks: how much data is sent and received over the network link (Wi-Fi or Ethernet) each second.

        Axes: bottom = elapsed time (minutes). Left = network throughput in MB/s.

        How to read: compare this against the Disk I/O tab at the same time. If the network line is low while disk is maxed, the network has spare capacity and is not the problem. If the network is maxed while disk is not, the connection is the bottleneck.

          Phase durations

          What it tracks: how long each stage of the migration took, from first contact between the PCs to the final report.

          Axes: bottom = duration in seconds. Each row (top to bottom) is one stage in the order it ran.

          How to read: the longest bar is where most of the time went — the stage worth optimising first. Copying files is almost always the longest.

          • File transfer — the actual file copy; usually the dominant stage.
          • Measured stage — duration taken directly from the app's own timestamps.
          • Estimated stage — the app doesn't time this stage, so the value is approximate.

          Data per drive

          What it tracks: how much data came from each drive on the old PC, split by what happened to it.

          Axes: bottom = one bar per drive (C:, D:, E:). Left = data in gigabytes (GB). Each bar is stacked into segments.

          How to read: taller bar = more data on that drive. The coloured segments show how much actually had to be copied versus what was already on the new PC.

          • Copied — new data transferred to the new PC.
          • Already existed — data already on the new PC, so it was skipped (saves time).
          • Remaining / skipped — data not copied (deselected or failed).

          File outcomes

          What it tracks: the number of files by what happened to each one. This counts files, not size.

          How to read: each slice of the ring is one outcome; a bigger slice means more files. A large red "skipped" slice means many files couldn't be copied — check the Skip reasons tab to find out why.

          • Copied — successfully transferred.
          • Already existed — identical file already on the new PC.
          • Skipped — could not be copied (see Skip reasons).
          • Backed up — an existing new-PC file was moved aside before copying.

          Skip reasons

          What it tracks: for the files that were skipped, the reason each one was skipped — grouped into categories.

          Axes: bottom = number of files. Each row is one reason, longest at the top.

          How to read: the top bar is the biggest cause of skipped files — fix that first to improve how complete the migration is.

          • Files skipped — count of files that could not be migrated, per reason.

          Transfer settings used

          What it shows: the settings the copy engine ran with. These control how files are copied (not what) — they are the knobs you change to speed things up.

          Where they live: the engine's config file (App.config / the deployed .exe.config), read by DellDataManager — not set by the app's screen.
